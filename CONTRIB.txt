EDITOR 0.6.14 - GUIDE FOR SOURCE READERS AND CONTRIBUTORS
======================================================

START HERE

editor.c is the complete editor implementation. It is one C99 translation
unit using libc and Unix terminal interfaces; keeping it in one file makes
the ordinary build and installation straightforward. liner.sh is a separate
program, not part of editor's runtime.

README.txt covers building, installing and using the source package.
docs/editor.txt and docs/editor.1 describe user-visible behavior.
docs/commands.txt is exported from the actual command registry.
This guide explains where to read and which implementation rules matter
when changing the program. Comments next to the code supply the details.

For a first read, start with the source header, Buffer, Change and
DocumentContext, then main(). Follow one operation from input to completion:

  Typing:       main -> key -> text_key -> edit -> replace_bytes -> draw
  Command:      main -> command_key -> execute -> the command's helper
  Saved file:   execute -> save_file -> journal_save
  Saved undo:   startup/read_document -> journal_load -> history_step
  Clipboard:    clipboard_open -> document_capture -> read_document
                clipboard_return -> document_restore

These are reading paths, not an exhaustive call graph. Paste, prompts,
menus and explicit key bindings have their own dispatch branches. Search
for function names rather than relying on line numbers, which change as
comments and code grow.

SOURCE MAP

  Types and file-local state
    Buffer owns byte storage. Change owns an undo record. DocumentContext
    temporarily owns the parked parent document while a clipboard is open.
    Most globals are used synchronously by the main loop. Signal handlers
    set sig_atomic_t flags; normal execution performs cleanup.

  Byte storage, positions and changes
    reserve, copy_buffer, decode, next_pos, prev_pos, representation,
    layout_at, edit, replace_bytes, history_step, history_move.
    These implement storage, display coordinates and in-memory undo.

  Files and persistent undo
    resolve_path, read_stream, read_file, ask_overwrite, journal_path,
    journal_load, journal_save, save_to_stdout, save_file.
    Follow save_file through its commit and cleanup paths before changing
    any error handling. File data and saved undo have separate commits.

  Help, commands and configuration
    command_info, command_lookup, command_overview, command_details,
    load_startup_config, save_preference, load_bindings, save_bindings,
    load_user_commands, save_user_command_table, execute.
    The command registry supplies names and guidance, not callbacks.

  Terminal protocol and presentation
    terminal_start, terminal_restore, signal_handler, dimensions,
    visible_from, draw_row, draw, byte, key, paste, main.
    Raw input, decoded keys, paste payloads and rendered text are separate
    layers. Keep that separation when adding a terminal interaction.

  Clipboard state and file navigation
    state_path, private_write, clipboard_set, clip_history_entries,
    document_capture, document_restore, read_document, clipboard_open,
    directory_next, directory_list, path_complete.

  Explicit external commands and scripts
    process_capture, insert_shell_output, run_script_file,
    execute_script_step, call_user_command, execute.
    Interactive aliases and script aliases intentionally use different
    dispatch paths. Read both before extending either.

OWNERSHIP AND UNITS

Buffer.n is a byte count and Buffer.cap is the allocation size. An empty
Buffer can be {0}; it does not necessarily own an empty C string. reserve
only ensures capacity. Document/string operations arrange a trailing NUL
where needed, while an undo record's old_s/new_s payloads are bounded byte
arrays rather than NUL-terminated strings. Document text itself rejects
embedded NUL bytes.

The active text and saved snapshot have separate ownership. saved is the
accepted content used by changed(); undo depth is not a dirty flag. Undoing
back to the saved bytes can make the file clean while journal_dirty remains
true because the history position still needs to be recorded.

cursor and top are byte offsets. left and goal are terminal-cell columns.
User-facing line numbers are one-based. UTF-8 movement is by decoded code
point, with invalid bytes handled individually; CRLF is a single movement
unit. The editor does not implement grapheme-cluster editing or shaping.
Tabs, wide characters and escaped controls make byte and cell counts differ.

representation and the layout cache must agree on those display widths.
layout_points and layout_recent are disposable derived state; text remains
authoritative. Byte edits invalidate checkpoints near the edit, including
the preceding bytes that could now form a UTF-8 unit or CRLF pair. Replacing
or switching the entire document resets the cache.

document_capture moves ownership into an empty DocumentContext and clears
the owning globals. document_restore frees the temporary active document,
moves ownership back, and clears the context. Do not copy these structures
as if their pointers owned independent allocations. A new per-document
field usually needs handling in capture, restore, read/startup and cleanup.
Global preferences and command history are deliberately not parked.

Viewers borrow their text. Static strings and persistent page buffers work;
a pointer into a returned function's local array does not. A reusable page
must not be overwritten while a viewer still needs its old contents.

EDIT AND SAVE BOUNDARIES

Use edit for a user-visible document mutation. It prepares the allocation
and undo payload before installing a new history node and changing bytes.
replace_bytes is the lower-level mutation helper used by edits and history
replay; calling it directly for a new feature would bypass normal undo and
other edit bookkeeping. Its inserted input must not alias text's storage.

history is the first node, history_tail the last, and current the last
applied node. current == NULL means the position before the first change.
A new edit after undo drops the in-memory redo branch. A saved older journal
may be archived; that is not a promise to retain an unsaved alternate future.
The typing group flag joins consecutive insertions; navigation and other
operations end the group. A complete terminal paste is a single edit.

save_file stages bytes beside the destination and publishes them with
rename or, for a new name, non-replacing link. Before that publication,
failure retains the old destination. After publication, a directory-sync,
metadata or journal problem cannot honestly be reported as though the file
was never saved. Preserve the distinction in both return state and messages.
Only remove temporary files actually created by that operation.

Overwrite approval is tied to an observed target version. The writer
rechecks that version before publication. These are optimistic conflict
checks, not a lock against another writer. Atomic replacement does not make
the document and its separate undo journal a single filesystem transaction.
write - is another case: bytes already sent down a pipe cannot be recalled.

Persistent undo records saved work, not unsaved crash recovery. journal_load
checks the saved format and its bounds before installing history. A valid
old journal may be extended with a synthetic change when an existing file
was edited outside editor. history_step also verifies the expected bytes
before applying an individual undo or redo operation. Keep the loader and
writer compatible when touching the format.

Clipboard copies use private files. They do not use a system clipboard API.
clipboard_set publishes the new slot before archiving its previous bytes;
a history warning can accompany a successful copy. History numbers are
positions in a new scan, not stable snapshot IDs across concurrent sessions.
private_write does not supply save_file's loaded-version conflict checks.

COMMANDS AND INPUT

For a built-in command, update command_info and execute together. Consider
menu entries, command completion, argument validation and error presentation.
The registry's aliases do not themselves implement the command. Review
allowed_key_command's policy when adding an action: recognized built-ins are
admitted by default except direct bind/unbind, while full argument validation
happens at invocation. Admission does not create a default key assignment.
Decide separately whether it belongs in execute_script_step; a command's
interactive availability does not make it appropriate for a script.

A direct user-defined command expands through execute, with normal prompts
and command behavior. For example, an explicitly defined quit! alias can
exit. Script aliases stay in the restricted script dispatcher. Scripts stop
on failure and have shared step/depth bounds, but earlier successful edits
remain undoable; a whole script is not one rollback transaction.

No commands execute merely because a document or definitions file is loaded.
shell and filter are explicit /bin/sh invocations with the editor's OS user,
working directory and privileges. Capturing their streams is not a sandbox.
The restricted editor-script command set does not restrict what an explicitly
invoked shell command can do to the filesystem or other accessible resources.
Undo reverses the editor's inserted/replaced bytes, not shell side effects.

process_capture drains stdout/stderr and tracks child status before output
can become an edit. Valid output plus a successful child exit and no pending
cancellation are all required. insert_shell_output makes the resulting edit
only after capture finishes. Avoid a blocking wait in the normal collection
path: a child can close its pipes and continue running.

key decodes terminal protocol; paste consumes bracketed-paste payloads.
A rejected, interrupted or timed-out paste must keep discarding through its
end marker. Its delayed tail must never become ordinary command keystrokes.
File reads and file-backed clipboard paste preserve bytes; terminal paste
and captured external output perform their own newline conversion.

main routes paste before ordinary modal dispatch so unwanted paste can be
consumed even while a confirmation or viewer is open. Command argument
prompts handle their own text before normal command execution. movement_key
does not insert text, but explicitly assigned bindings are dispatched first
by text_key and may invoke editing commands even in movement mode.

Configuration, definitions and key maps are separate persistence paths.
save_preference preserves unrelated config content; definitions are staged
before replacing their in-memory table. An explicit key binding can remain
active in the current session when saving it fails. Read each helper's
contract rather than imposing one assumed failure policy on all three.

BUILDING AND CHECKING A CHANGE

From this directory, build with the same strict flags used by the runner:

    cc -std=c99 -O2 -Wall -Wextra -Werror -pedantic editor.c -o editor
    ./editor --version

The existing regression runner builds into a temporary directory and runs
C checks plus Python terminal tests; it does not install the editor:

    sh tests/run.sh

It accepts CC to choose the compiler and SANITIZE=1 to enable AddressSanitizer
and UndefinedBehaviorSanitizer on platforms/toolchains that support them:

    CC=clang sh tests/run.sh
    SANITIZE=1 sh tests/run.sh

Python 3 and Unix pseudo-terminals are development-test requirements, not
runtime dependencies of the installed editor. The tests deliberately
exercise process signals, job control, subprocesses and filesystem failures.

The core C harnesses include editor.c after renaming main, allowing tests to
call file-local helpers without exposing a public API. safety_driver.c keeps
the editor entry point and wraps selected calls for terminal tests. Several
harnesses wrap allocation and system calls to inject failures. When changing
one of those paths, read the wrapper and its assertions; a successful normal
run alone does not exercise the failure ordering that the test is checking.

Useful entry points in tests/:

  core.c, safety_core.c, safety_driver.c
    Buffer, history, persistence and injected failure behavior.
  command_stability_core.c, command_stability_terminal.py
    Alias/script routing and command consistency.
  external_stability_core.c, external_stability_terminal.py
    Child capture, cancellation and output commit behavior.
  paste_terminal.py, paste_stability_terminal.py
    Newline conversion and delayed/cancelled paste framing.
  layout_core.c, layout_terminal.py
    Differential byte/cell positions, cache invalidation and rendering.
  keymap_stability_core.c, keymap_stability_terminal.py
    Keymap parsing, concurrent saves and session-only failure state.
  startup_terminal.py, settings_terminal.py, toggles_terminal.py
    Saved preferences and their UI behavior.
  signals_terminal.py, persist_signals_terminal.py
    Signal and persistence interactions.

tests/run.sh is the authoritative list of the ordinary regression checks.
Other files cover focused compatibility, fuzzing and performance work.
Historical results under tests/results refer to the source revisions named
in VALIDATION.txt; they do not automatically certify a later code change.
Native OpenBSD behavior needs verification on OpenBSD, especially terminal
and job-control paths. A Linux test result is not an OpenBSD test result.

KEEPING DOCUMENTATION USEFUL

Explain ownership, units, caller obligations, failure states and the reason
for a non-obvious branch. Avoid comments that just repeat the next statement.
When a check is optimistic or cleanup is best effort, say that explicitly.
Keep the rationale beside the operation it constrains.

When command behavior changes, update the built-in strings, command registry,
README and relevant manual sections. Regenerate the command reference with:

    cc -std=c99 -O2 -Wall -Wextra -pedantic tests/export_guide.c -o export-guide
    ./export-guide > docs/commands.txt

For a comment-only change, compare preprocessed C from the old and new source
with identical compiler flags, include paths and predefined macros, and build
with warnings as errors. This catches an accidental code change or a comment
that swallows code. It does not check whether the prose accurately describes
the implementation; that still needs review against the actual code.

This pass retains version 0.6.14. CHANGES.txt identifies the comment maintenance
separately, and VALIDATION.txt records its checks without presenting the older
performance measurements as a new benchmark run.
